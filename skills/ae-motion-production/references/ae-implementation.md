# AE 工程实施要点

## 修改已有工程

先确认当前项目路径、目标合成和图层结构，再修改。操作使用检查得到的对象引用或可靠的名称，不硬编码“第 13 层”这样的易变编号。用户说的是父级列中的数字时，解释它是该合成内的图层序号。

另存版本保留已有成果，不静默打开磁盘旧版本覆盖当前未保存的手工调整。新脚本尽量幂等：发现已存在的控制器或效果先检查，再更新；失败后先确认执行到了哪一步，不盲目重复建层。

## 路径绑定到开合控件

优先使用对场景合适的刚体/分面结构。需要 SVG 路径过渡时：

1. 保存闭合和打开的完整路径数据：vertices、inTangents、outTangents、closed；保留局部坐标系。
2. 配对两端轮廓，确认顶点数量、起点、顺序、方向和子路径对应。数量不一致时，通过曲线细分或重新拓扑建立对应；不要任意重复顶点以凑数量，必须检查插值过程是否折叠。
3. 在“控制器 · 箱盖”的“开合程度”滑块设置时间关键帧。主动作所需的缓动放在滑块曲线上。
4. 路径表达式读取 `clamp(控制值 / 100, 0, 1)`，对对应顶点及两侧切线插值，以 `createPath` 返回形状。状态数据可保存在表达式或明确命名的数据层中，不额外依赖逐帧图片。
5. 子路径不再保留独立的开合时间关键帧。需要延迟显露的内腔、轮廓或光效，用控制进度的区间映射驱动；确实需要独立时间时另设有职责的控制参数。

不要同时对控制器时间插值和路径进度重复套强缓动，否则中段速度容易失真。0、50、100 等数值应可独立预览；调节滑块时整个盖子应可靠响应。表达式里的效果名和层名必须与工程一致。

AE 的路径属性本身不显示完整顶点坐标数值表；这些数值可通过 Shape 数据读取。不能因此让用户只能钻进每条路径调动画。应把常用可编辑数值暴露在控制器中。

## SVG 和 Shape 数据

- 不假设 SVG 可直接作为 AE 可编辑形状导入；使用当前软件支持且验证过的转换流程，保留路径与分件结构。
- 检查渐变坐标、透明度、蒙版和填充规则。普通颜色填充不能替代所有原始材质层次。
- 在脚本中先用普通数组构造所有顶点，再一次性赋给 `Shape.vertices`。不要先给它赋空数组后逐项追加。
- 预合成中向上抬起或向外展开的路径可能被边界裁切；增加留白时，配套调整坐标与外层锚点，确保屏幕位置不变。
- 全局原点适合数据转换，不等于交付时合理的操作锚点。用控制器提供明确的操作基准。
- 多张图标先去重并确认清单；按可见轮廓边界与视觉中心统一展示尺度，不按包含不同留白的图片尺寸直接等比缩放。
- 自行转换 SVG 时先确认实际用到的路径命令与变换。展开嵌套矩阵时同时处理顶点、切线、渐变坐标及裁切轮廓；切线作为相对向量，不能再叠加平移。不支持的命令应显式报告，不能静默丢弃。
- 区分渐变的 `userSpaceOnUse` 与 `objectBoundingBox`。复合路径孔洞、evenodd 填充、组透明度和裁切需要单独核对。AE 新图层插在顶部，转换后检查遮挡顺序。
- 原生路径配内置渐变效果是一种可行方案，不必把所有渐变改成纯色。先验证代表性图标（透明孔洞、宝石裁切、非对称外形），再批量处理其余素材。

## 完整中文命名

批量改名之前，**先把项目面板中的所有 item 对象保存为固定数组**。重命名可能改变项目面板排序；边按 `project.item(i)` 遍历边改名会跳项或重复处理。

逐个合成检查全部图层，而不只是当前合成或选中层。包含父级控制器、隐藏层、停用层、形状分组和自定义效果。材质零件优先按作用命名，如“箱盖 · 锁扣高光”，避免仅用无意义的轮廓编号。

改名后检查按名称引用的表达式。不要对表达式全文做没有边界的字符串替换，误改代码或文案。验收清单按 item ID、合成和图层计数去重，确保没有跳过合成；检查实际工程，不能只相信脚本写出的“完成”状态。

## AE 执行与渲染

- 先检查当前 AE 版本、进程、项目和可用渲染模板，不硬编码其他机器的安装目录或输出模板。
- 父级绑定或锚点调整可能改变现有局部变换；在代表时刻比较屏幕位置和形状，避免引入跳动。
- 渲染队列中只操作本次目标项及必要的待渲染项，不改已完成项的 render 状态，也不清空用户已有队列。
- 避免重复提交还在执行的渲染。读取状态文件或渲染结果，超时不等于失败；不要无依据结束用户 AE 进程。
- 可从 AE 输出支持的中间视频格式，再编码 MP4。确认最后的视频确实来自最新工程，检查时长、帧率、画面和末尾状态，不能把静态分镜当动画交付。
- 检查表达式错误，并实际采样/渲染关键状态。不要只依赖“表达式已赋值”或“项目已保存”。

### 本次遇到的脚本兼容问题

- AE 的索引属性组在 `addProperty` 后可能使先前持有的 Property 引用失效，尤其是连续添加效果控件时。记录层与属性的稳定标识；批量添加完毕后重新获取滑块，再采样、改关键帧或验证，避免“对象无效”。
- 在本次 AE 22.0.1 环境中，`CompItem.shutterPhase` 需要整数；相机兴趣点的 Transform matchName 是 `ADBE Anchor Point`，不能凭显示名称猜为 `ADBE Point of Interest`。遇到 null 属性时先检查实际属性树，不把特定版本的经验当作所有版本的保证。
- 启动命令返回成功不代表 JSX 已执行。让脚本写入带时间或运行标识的阶段状态，并验证输出文件更新时间；陈旧状态文件不能证明本次成功。
- Windows 上本次可用的诊断入口是安装目录内的 `AfterFX.com -m -r <脚本>`，以该程序所在目录为工作目录可保留控制台输出。这是已验证的备选入口，不是固定安装路径或每次启动的必需参数。`-m` 会创建独立实例，不用于盲目重试；诊断先从最小脚本开始。
- 检查进程时兼顾 `AfterFX.exe` 与 `AfterFX.com`。已有实例、启动中实例和未返回的渲染要区分；不要在无结果时连续启动多个实例。保留用户当前工程；在确认本次脚本的失败阶段后，优先从已生成的合成继续验证和保存。
- 工程建立与验证通过后先保存，再输出代表帧和完整视频。状态记录应区分“保存完成”“渲染中”“渲染完成”，便于失败恢复。只在真正完成后编码 MP4，并检查实际解码帧数、帧率和末帧。

## 面向用户的控制说明

给出真实可操作的位置，例如：“进入紫色宝箱合成，选中‘控制器 · 箱盖’，按 U 查看‘开合程度’关键帧；0 关闭，100 打开。”主要控制器不要默认设为害羞隐藏。

用户看不到锚点时，先检查图层控件显示、当前选择的是图层还是路径、锚点是否在画外或合成原点。不要未经确认直接给所有层居中锚点，以免改变现有父级和动画。

## 横向轮播与选中反馈

适用于抽取装备、道具循环展示或类似中央聚焦的队列。此处来自一次竖屏横向轮播制作；装备数量、色彩和时长按当前任务决定。

### 队列与画面

- 先从草图确定画布比例、横向或纵向运动、中央尺寸、两侧露出多少。横向轮播不自动变成老虎机，也不因为“抽取”就添加抽奖机外壳。
- 每件装备独立预合成，使用可见边界中心作展示基准，以最大可见边长归一化，再做视觉校正。长剑与宽盾共用素材画布尺寸时，留白不同会导致错误缩放。
- 一个轮播控制器集中提供进度（以格数计）、中奖序号、中心大小、两侧大小、间距与整体位置。图标的位移、大小、透明度从同一进度推导，避免各自缓动造成错位。
- 中间放大、两边缩小应连续变化；层级按距中心的距离排序，中心遮挡边缘。若使用 AE 3D 图层作深度排序，可保持插画正对镜头，不将二维体积插画沿 Y 轴翻成薄片。

### 可复用的循环关系

令 N 为图标数，i 为图标序号（内部从 0 起），q 为连续队列进度。最近的一圈位置可用：

```js
const d = ((i - q + N / 2) % N + N) % N - N / 2;
const focus = Math.exp(-k * d * d);
const x = centerX + d * spacing;
const scale = sideScale + (centerScale - sideScale) * focus;
```

k 控制中央放大范围，按构图调节。双重取模用于处理 JavaScript 的负余数。换圈接缝安排在不可见区域，并在出入边缘淡出，避免突然跳回穿过画面。

若通过远离镜头的 Z 值排序，并希望保持上述屏幕坐标和尺寸，以镜头距离 L、深度 z 得到补偿系数 `r = 1 + z / L`，对相对镜头中心的平面偏移和图层缩放乘 r。只在已确认的镜头朝向及坐标约定下使用，并以实际渲染核对；不要重复应用透视缩放。

连续抽取时保存当前中心 start 与目标 target。可使队列从 start 出发，最终进度为 start 加整数整圈数再加目标偏移。让偏移随主进度平滑加入，不能在结果时突然替换中奖图标。中奖项、居中位置与文字结果使用同一序号来源。

### 节奏与揭晓

动作顺序：触发反馈 → 加速 → 快速轮转 → 连续减速 → 准确停中 → 轻微回弹与光效 → 结果停留。

- 快速区检查连续速度，减速区让图标逐渐可辨。统一控制器曲线负责速度，不再给每个图标额外套一层强缓动。
- 停点必须准确落在目标格数；微小过冲可以强化停中感，但回弹后位置和大小应恢复正常。
- 选中反馈可叠加短促暖光、向外扩散的双层光圈、放射线与散射星芒。光圈位于装备后方，星芒避开重要轮廓，避免闪白掩盖装备。层数与强度依据参考，不作为所有作品必需效果。
- 本次增强效果约在 0.7 秒内收掉，是可调整的案例值。用单独的“命中进度”和“光效强度”控件驱动半径、透明度和粒子位置；以共同命中时刻为基准，便于同步移动。
- 用户只要求加强最后选中时，在已确认工程上另存增量版本，保留之前的轮播速度、停点及素材细节。

### 验证

先检查代表性中间帧，再完整播放：启动、快速区、换圈、减速、刚命中、回弹极值、光效消失后。关注图标穿插、遮挡反转、边缘裁切、拖影强度、文字避让和残余漂移。

逐个切换中奖序号检查结果；可重复抽取时检查不同起点到不同终点的组合。本次 10 件素材检查了 100 种组合；以后按实际数量与风险选择覆盖范围。移动主控制器关键帧，确认所有依赖图层一起响应；验证后恢复关键帧和默认中奖值。

## 前端还原与作品发布

仅在用户要求已有 AE 动效的交互版本或发布作品时使用。单纯要求总结经验，不修改旧工程、网页或线上内容。

### 从工程还原，不靠猜曲线

- 使用已经确认的最终工程版本（包括后加的选中反馈）。共用矢量路径、渐变、素材边界和名称，避免重新绘制一套近似图标。
- 优先导出关键帧插值，或使用 `valueAtTime(t, false)` 从实际起作用的控制器采样。采样表保留通道名、时间单位、采样率和总时长。一次案例使用 120 Hz 采样后线性插值；采样率应根据动作速度和误差验证选择，不要求永远使用 120 Hz。
- 在 AE 帧边界及动作极值对照。采样插值存在数值误差时使用与画面精度相关的容差，不把浮点严格相等当作视觉正确性标准。
- 前端沿用同一周期位置、大小和透明度关系。只有真正需要透视时才重建相机；已投影到屏幕空间的坐标不能再次透视缩放。
- Canvas 中由矢量路径生成清晰的离屏缓存，可降低多图标逐帧重绘成本；控制缓存尺寸和设备像素比，兼顾手机内存与清晰度。运动模糊可按快门时间采样若干时刻再合成，避免使用明显滞后的固定拖尾。
- 形状、渐变、模糊、混合模式与字体需要各自比对。复用曲线和坐标不代表所有浏览器逐像素相同；没有对应渲染验证，不宣称“100% 像素一致”。

### 把视频时序变成可操作状态

明确加载、待机、抽取中、结果、重置与加载失败状态。待机等待真实点击，不直接自动播放一段视频冒充交互。触发后再推进时间线；保留点击反馈。点击光圈应对应实际指针位置，键盘触发使用合理的默认位置。

- 选定结果后锁定本轮目标，动画与结果文案读取同一个值。是否随机由产品要求决定；前端随机演示不等于正式抽奖服务。
- 抽取中防止重复触发；重置应取消旧动画回调。再次抽取从当前中心开始，避免瞬间跳回初始装备。
- 用真实按钮支持触摸、空格和回车，提供可见焦点和结果播报；加载失败可重试。减少动态效果偏好可以直接呈现结果或采用简化过渡。
- 页面隐藏后暂停或修正计时，避免切回时突然跨过整个揭晓过程。手机检查舞台比例、控制区高度和横向溢出，嵌入页还要检查 iframe 的实际内容高度。

### 对照检查

分别检查视频与前端的同一时刻：中央及两侧尺度、运动方向、加减速、停点、回弹、星光轨迹、光圈层级、文字基线和结果停留。静态并排截图用于细节对比，完整播放用于节奏验证，不能互相替代。

验证至少一次真实点击、键盘触发、继续抽取与重置。数学验证可覆盖不同起止序号的准确停中；它不能替代浏览器中的画面和交互检查。若提供指定时刻/结果的检查入口，使其显式可识别，普通访问仍进入正常交互。

### 发布到已有作品集

- 先查看用户指定参考作品的真实页面和源码，复用现有框架、字体、间距与导航。本次采用“标题 → 视频 → 实际体验”布局，这是该博客的既有约定，不是所有作品集的默认模板。
- 保留用户指定标题，将视频和体验接入同一详情页，并补齐列表入口。工程下载仅在需要时加入，不自动公开工作文件。
- 发布前构建、检查资源链接，并实测嵌入布局。确认发布仓库与本地源目录的关系；仅同步本任务文件，保留无关未提交修改。
- 以当前远端版本为基线，只发布明确的文件清单。网络失败不能直接改用强制推送。若使用已授权的 API 发布路径，检查远端是否变化、保留现有树、仅非强制更新分支，不在输出中暴露凭据。
- 区分上传成功、构建部署成功和线上可用。最后核对详情页、视频、脚本、矢量数据及时间线资源，并尽可能在线点击验证。浏览器验证受阻时如实区分已完成的本地验证与线上资源检查。
