# 角色与 IP 表情的柔性动效

用于已有可编辑角色的表情扩展、柔性绑定和批量动画交付。先看实际角色与参考视频，再选择变形结构；不要把某次角色的时长、幅度和部位清单固定套到所有项目。

## 先解决“像整张图片晃动”

分了很多层、加了很多表达式，不代表角色有生命力。用户反馈生硬时，先检查主体是否只在整体旋转或位移，各部位是否始终保持同一个相对姿态。判断依据是连续播放的动作，而不是图层数量和技术检查通过。

观看参考的连续动作，找出压缩、伸展、转向、停顿和跟随的先后关系。把参考确实表现出的动作与自己补充的手势区分开。先做有代表性的试片，例如弹跳、探看和舞动，自行检查后再扩展整套。

用清楚的动作因果组织各部位：

- 身体承担蓄力、发力和重心变化。上身弯曲与整体转角应分开，身体轮廓要真的改变。
- 五官随身体移动，但保留视线、眨眼、眉毛和嘴型的独立节奏。探看可以由眼睛先看、头身后跟；不能把“所有五官都延迟”当作通用规则。
- 卷毛、耳朵等柔软末端稍后跟上，并有幅度逐渐减小的回弹。连接点应连续，不能像贴上去的零件滑动。
- 手脚围绕同一次发力安排不同轨迹和相位。起跳前压低，离地时伸展，落地后压缩；接触地面时检查脚底漂移，阴影配合高度变化。
- 不同情绪使用不同动作句子：拨眼镜、抽泣、打哈欠、害羞捧脸各有主次。不要给每个表情换一套脸后复制同一条左右摇摆曲线，也不要求每个部位一直运动。

关键帧经过中间姿态时保留连续速度；只在有意停顿处收至零速。Auto Bezier 可作为起点，但需要检查过冲和节奏，不能把所有关键帧统一强缓动视为完成。

## 曲线与分件关系

静态矢量先核对外轮廓弧度、卷曲内侧、尖端、凹口和色块接缝，再做动画。用少量合理的三次贝塞尔段描述轮廓；圆滑连接处检查切线方向，保留有意设计的尖角。透明凹口不能靠白色补丁伪装。

柔性变形可由同一坐标映射驱动身体及附着色块，减少不同层分别缩放造成的错位。以脚底或实际连接点为基准做挤压伸展；二维软团角色可以用 `sx ≈ 1/sy` 近似保持面积，但这只是造型手段，仍需按视觉调整。

非线性变形不能只移动路径顶点、留下原来的切线。同步变换切线，必要时用局部雅可比或中心差分近似。长曲线若变形不足，可用保持原曲线的细分增加控制密度；先选最低够用的密度，并测试多角色组合的性能，不默认给全部路径大量加点。

瞳孔受眼白边界约束，舌头受口腔约束，腹部和卷毛内侧色块随身体边界变化。使用矢量遮罩保护边界，但遮罩不能代替正确的几何贴合。检查最大压缩、最大伸展、闭眼和大幅视线转移时的穿出、白缝、折叠与双重轮廓。

## 可编辑绑定

按职责提供整体、弹性身体、表情、手势和点缀控制器，具体数量随角色结构决定。身体可暴露压缩拉伸、弯曲、柔软末端摆动等参数；五官和四肢使用各自必要的参数。关键帧在这些真正驱动路径的控件上。

跟随延迟从同一个动作时间源读取，循环动画要处理负时间取模。检查循环两端的姿态、速度和粒子相位，不能只令第一帧与最后一帧的位置相同。

保留 SVG 的分件和实际曲线路径，验证 Illustrator 打开后仍可编辑；SVG 可以作为矢量交付格式，但不要改扩展名冒充原生 AI。AE 角色使用原生形状与控制器。静态源文件和动画中改过的填色、轮廓应保持一致，预览成片不能替代可编辑角色源文件。

## 批量输出与恢复

先验证单个角色，再测试小规模组合的实际渲染。单个角色成功不证明全套同时计算也稳定；尤其注意密集 `createPath` 表达式、跨层路径引用和动态遮罩的组合。

把建工程、保存、单个角色渲染、总览、编码和打包分成可恢复阶段。状态文件带本次运行标识或时间。等待时同时看对应进程是否还在、退出码、日志和输出是否推进；陈旧的“渲染中”状态或非零大小的残缺视频不能证明仍在工作。不要只盯状态文件无限等候。

命令行 AE 实例结束后，`scheduleTask` 不能被当作可靠的后续任务队列。需要继续时，确认上一阶段已经结束，再打开已保存工程运行明确的下一阶段。

一次本机 AE 22.0.1 案例中，13 个独立柔性角色全部渲染成功，但全套原生组合退出；新实例单独渲染及关闭多帧渲染后仍退出。根因没有确证，不把它归结为已证实的内存不足，也不把关闭多帧渲染当作必然有效的修复。

若组合渲染重复失败，可用已经验收的独立成片汇总总览视频，同时保留每个角色的原生工程。总览属于展示预览，不应以视频层替换用户要求可编辑的角色。保留已有总览内容，优先使用可逆的停用显示或调整默认打开合成；若交付中有停用内容或单独汇总的预览，说明用途与限制。不要为解决预览问题默认删除可编辑内容。

确认每个输出已完成后再编码，可按已完成项逐个推进。依据实际元数据和解码结果检查帧数、时长、尺寸和帧率，不把某次 AVI 的固定字节数当作通用完成条件。

## 透明度、播放与验收

- 先确认中间文件的 alpha 是直通还是预乘，以及实际底色。转为透明 WebP 等格式时仅在确属预乘的情况下去预乘；白底预乘可按 `C = (Cpremul - (1-a)·白色)/a` 还原，处理零 alpha 和数值截断。换成其他底色需相应修改。
- PyAV 的 `frame.to_image()` 不适合作为保留 alpha 的默认步骤；显式读取 RGBA，例如 `to_ndarray(format='rgba')`，并检查实际通道。透明输出放在深色或棋盘格背景上检查边缘。
- GIF 帧时长以百分之一秒计，30 fps 可用 30/40/30 ms 分配近似并保持总时长；MP4 用于准确检查帧率。共享调色板可减少扁平配色闪烁。最终仍需实际播放，不能只验文件扩展名。
- 接触表检查轮廓与极值，连续播放检查节奏和协调；分别执行。首尾像素差、帧差和内容边界可辅助定位问题，不能证明动作自然，也不能替代用户的视觉认可。
- 分清“原生工程验证通过”“单个成片完成”“总览完成”和“用户认可”。未获得新的视觉反馈时，不把技术完成记为用户已认可风格。

交付主工程、必要的矢量源文件、可播放预览和简短控件说明。逐个检查压缩包里的文件及引用完整性，避免把无损中间渲染、试片和临时制作脚本默认全部塞进交付包。
