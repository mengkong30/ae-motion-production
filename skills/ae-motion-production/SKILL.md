# 动效制作与可编辑工程

目标是同时交付可信的运动效果和用户能接手修改的工程。使用用户指定的软件；以下为该用户的默认偏好，具体项目的新要求优先。

## 默认制作约定

- 优先少量 SVG 源素材和软件原生形状、文字、光效。按运动结构分层，不按帧导出素材，不用逐张位图拼装矢量动画。视频预览和用于检查的抽帧不属于动画源素材。
- 整个工程使用有意义的中文名称：项目文件夹、合成、所有预合成内部图层、控制器、形状分组、可命名的效果实例和分镜标记，包含隐藏及停用图层。软件内建参数名、表达式语法和素材格式不强行翻译。画面文案是否翻译另依设计要求。
- **关键帧打在真正起作用的控制器上。** 不把一组动作分散到许多子图层后，留下一个没有动作的“控制器”。形状细节可以分层；对外的动作参数要集中。
- 确认结果时同时检查视觉、动作完整性和工程可编辑性，不能把“成功保存/渲染”当成完成。

## 先读懂参考，再决定结构

查看实际参考视频的连续运动，并抽查动作前、中、后及极值帧。明确观察到的行为和自己补充的设计；看不到参考时，不声称已经匹配。

区分画布方向、运动方向和参考用途：竖屏不等于纵向滚动；用户画的横向队列、中央放大与两侧露出，应按这种构图实现。参考旧作品的美术风格时，提取配色、字体、材质与光效语言，不自动沿用它的动作结构。用户指定沿用的已有作品，先定位实际文件并查看。

先写一个简短动作顺序，标出触发、预备、主动作、回弹和停留。区分用户点击与自动变化，避免省略一次必要的交互反馈。时长和幅度从参考及用户反馈决定，不机械套用固定秒数。

按刚体、连接点和遮挡关系拆分素材。例如宝箱分箱体、箱盖、内腔和光效；先确定箱体是否固定、铰链在哪、打开后哪些面会露出。检查弧顶、圆角、金边厚度、锁扣比例和闭合接缝。

先完成没有复杂光效的基础运动，并自行检查。仅需用户做关键视觉选择时再询问，不把每个制作阶段变成审批流程。

## 控制器是动画的入口

建立“控制器 → 子层/路径/效果”的明确关系：

- 整体动作：位移、旋转、缩放等关键帧放在整体控制器；零件跟随。可用实际变换属性或明确的效果控件，不强制一种实现。
- 分件动作：如“控制器 · 箱盖”添加 **开合程度**，`0 = 关闭，100 = 打开`。开合关键帧放在该滑块，所有盖子路径、内腔显露和必要的材质变化由它驱动。
- 光效或粒子需要独立节奏时，使用有明确职责的光效控制器/参数。不要为了“集中”把所有动作塞进一个巨大控制器。
- 路径变形允许使用，但必须由控制参数驱动。不要同时保留子层独立时间关键帧和控制器动画，形成两套互相冲突的时间来源。
- 给参数写清单位、范围和正常值。优先让“整体大小 100%”表示正常尺寸；若必须保留素材适配缩放，解释它与相对动作幅度的区别。
- 主要控制器默认可见、可选，不设为隐藏的害羞图层。锚点应符合铰链或缩放基准；不要为了看起来居中破坏运动。

验收时手动或用脚本采样控制参数的起点、中间值、终点；确认零件一起响应且边界状态正确。关键帧必须能在控制器上通过 U 找到。移动控制器关键帧后，依赖动作也应随之改变。

## 动作与光效

以结构正确为先：不要用箱体向下移动伪装开盖，也不要将带体积外观的整块二维插画当作一张平面翻转，造成盖子压扁或透视断裂。根据视角选用刚体转动、分面结构或受控路径过渡。

需要“点击后打开”时，保留清晰因果：点击反馈 → 抖动/蓄力 → 主动作 → 回弹收稳。缩小再放大可以强调能量释放，幅度按当前任务决定；默认等比缩放，除非参考明确使用挤压拉伸。最后应准确回到正常大小和预期位置，避免残余漂移。

光效要有来源和遮挡：从实际开口逐渐透出，再扩散、衰减。让箱体、盖子和内容物仍然可辨，避免一大片突兀的扇形或闪白掩盖结构问题。

星光不能只停在原地改透明度来冒充流动。参考其方向、速度、轨迹、密度与前后层次，安排错峰出现、运动、闪烁和退出；需要时加入少量拉长光点及运动模糊。优先原生路径、粒子系统或分组复用，不为每颗星新增外部素材。

## 角色与表情动效

角色需要身体、五官、柔软末端与四肢围绕同一次发力配合；分层本身不等于灵活。用户反馈像整张图片左右晃动时，先检查相对姿态和轮廓是否真的变化。制作这类任务时读取 [角色柔性动效与批量交付](references/character-motion.md)，其中包含曲线连续性、延迟跟随、遮挡、透明输出及组合渲染失败的处理经验。

## 检查与交付

对照参考观看完整播放，再检查动作极值和中间帧：闭合、缩小、放大、半开、全开、回弹后。重点找比例突变、路径折叠、脱节、错误遮挡、裁切和漏光；接触表仅辅助检查，不能代替观看运动。

检查控制器确实驱动动作、表达式无错误、所有合成内部名称完整、主要控件可发现、工程没有不必要的外部素材依赖。改动时保留此前已确认的动作和细节，不用重新生成整个工程覆盖用户手工修改。

交付可编辑工程和可播放预览，简短说明修改内容，以及用户应选哪个控制器、调哪个参数。用户只要求总结或记住经验时，不修改旧工程。添加到作品集或发布属于单独的用户任务，不因制作完成自动执行。

在 AE 中脚本制作、路径绑定、批量改名或渲染时，读取 [AE 工程实施要点](references/ae-implementation.md)。其中也收录横向轮播、选中反馈与前端还原经验；仅在用户要求交互版本或作品发布时使用相关部分，不自动授权发布。
